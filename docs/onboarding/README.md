# Onboarding tour

Welcome. This tour takes about 30 minutes and answers four questions: what is this, what can I run, where is the work, and how does my change get reviewed. It is written for developers first. Page 05 is for people who do not write code.

| Minutes | Page | You get |
|---|---|---|
| 5 | [01 What and why](01-what-and-why.md) | the idea and what does not exist yet |
| 8 | [02 Run it](02-run-it.md) | a working checkout and a green check |
| 5 | [03 Pick work](03-pick-work.md) | a unit you can finish in about an hour |
| 7 | [04 Make a change](04-make-a-change.md) | branch, verify, commit, pull request |
| 3 | [05 Without code](05-without-code.md) | design, research, policy, translation paths |
| 2 | [06 Review and decisions](06-review-and-decisions.md) | what happens after you open a pull request |

## The 30 minute path

1. Read page 01.
2. Run `bash scripts/bootstrap.sh --check`, then `bash scripts/bootstrap.sh` (page 02).
3. Open [good-first-units.md](../contributing/good-first-units.md) and pick one unit (page 03).
4. Claim it in an issue, branch, change, verify, open a pull request (page 04).

Other entry points: [CONTRIBUTING.md](../../CONTRIBUTING.md) is the full contribution guide, [docs/contributing/README.md](../contributing/README.md) explains how units are chosen, and [.github/README.md](../../.github/README.md) explains the issue forms and labels.

This tour links to rules and does not copy them. When a page here and a linked file disagree, the linked file wins; please open a docs-fix issue.
