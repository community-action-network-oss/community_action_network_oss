# 05 Without code

Every profession is welcome. See [participation](../spec/20-participation-nonmonetary.md) for how the project grows. Engineers are the most urgent need today, but lawyers, rights and policy experts are needed now too.

| Path | Start here |
|---|---|
| **Design** | tokens, screens and flows in [docs/design](../design/README.md); review a wireframe and say what is unclear |
| **Accessibility** | read a screen spec or the app and report contrast, keyboard, screen reader or reduced motion problems via a bug issue |
| **Research** | pick an [open question](../open-questions/README.md), add sources, options and trade-offs |
| **Policy and law** | domain experts can draft or review rules for `can_policy`; the good-first index forces in data-only units that need legal reading, not code |
| **Translation** | check plain-language and translated strings for meaning; say clearly what you are unsure of |
| **Docs** | use the docs-fix issue form for an unclear or wrong sentence |

## Working on an open question

1. Pick one whose "Who can help" line fits you.
2. Read "Current default" so you know what is already assumed.
3. Open a pull request that adds a `## Proposal` section to the question file, or open the open-question proposal issue form.
4. Cite sources. Do not include real personal data. Disagree with evidence; popularity does not decide these questions.

The register README explains the full flow: [docs/open-questions/README.md](../open-questions/README.md). You do not need Git skills for your first contribution: a docs-fix or proposal issue is welcome.
