## Objective
A single skeleton and a lint so the DP directories written by 10-u15 to 10-u19 and 10-u62 to 10-u65 (28 in total after lifecycle v2) are uniform and machine-checkable.

## Steps
1. `decision-points/_template/` with `prompt.md` (sections ROLE, RULES `{{RULES}}`, OUTPUT, EXAMPLES `{{SHOTS}}`, DATA block with fixed delimiters from docs/design/ai/runtime.md), `schema.json` (extends `../../schemas/dp-output.schema.json`), `pack-section.yaml`, `examples/.gitkeep`, `eval/` with empty `core.jsonl`, `adversarial.jsonl`, `thresholds.yaml`, `README.md`. `tools/new-dp.mjs DP-NAME --rules A,B --outcomes x,y` copies and fills it; `npm run new-dp -- ...` script.
2. `tools/lint-dp.mjs` (called from `lint.mjs`): each directory under `decision-points/` except `_template` must have all files; `schema.json` outcomes are a subset of the six outcomes and equal `pack-section.yaml` outcomes; `escalate_human` appears only in DP-CRISIS and DP-LEGAL; every id in `enforces` exists in `packs/*/rules.yaml` (skipped with a printed reason until 10-u06 lands); the prompt contains the DATA delimiters exactly once and no template variable other than `{{RULES}}` and `{{SHOTS}}`; examples files parse and match the case shape; example ids are unique across the DP; `eval/core.jsonl` ids and inputs are disjoint from examples; `thresholds.yaml` has the keys named in 10-u15.
3. `prompt_hash` helper `tools/prompt-hash.mjs`: sha256 of the rendered template before data insertion (with `{{RULES}}` and `{{SHOTS}}` left as literal markers), documented as the definition used by the server in plan 09.
4. Tests with fixture DP dirs: valid passes; each rule above fails with an expected message.
5. `docs/writing-a-dp.md`: 1 page for contributors: how to add a DP or an example, what the lint checks, the no-real-people rule.

## Acceptance
- A DP directory generated by `new-dp` passes lint once examples exist.
- Every lint rule above fails in a test.
- `npm run verify` green.

## Out of scope
- Real DP content (10-u15 to 10-u19).
